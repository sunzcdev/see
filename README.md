# 兮 · 命理压缩法

> **兮**（see）—— 一个命理顾问的名字。这里放的是它的作业底稿。
>

> **把「算命」从一句判决，做成一条有分寸的断语。**
>
> 核心命题：玄学全行业只处于**模糊**状态——只能把模糊变清晰（增强约束、缩小可能性空间），**做不到精确，更做不到准确**。
> 所以本方法的产出不是「你会发财」，而是「在这几个条件下，这件事的可能性空间从这么宽缩到这么窄，把握七成」。

---

## 这是一个什么仓库

一套**断语的证据纪律**，外加一条**可重放的验证流水线**。

- 起因：手上有四类材料——经典骨架（《子平真诠》系）、流派条件（巾箱秘术）、机制路径（道秀说易）、以及数千条真人案例库。
- 问题：四类材料各有各的说法，谁对谁错？**不能靠"我觉得"**。
- 做法：把四类材料蒸馏成**可检验的条目**，先在案例库上按预注册判据跑一遍，再定档。

方法论正文见 **[`METHOD.md`](METHOD.md)**。

---

## 方法骨架（速览）

**五格**：任何一条断语必须交代 —— ①条件 ②方向 ③强度 ④机制 ⑤冲突边界。

**四档**：`A` 可用 ／ `B` 待观察 ／ `C` 参照 ／ `D` 禁用。

**三把刀**：切域（这件事属于哪一类事）｜比基线（比这个人自己的历史，不比人群平均）｜标档位（说方向就给可检出线）。

**四源合一**——不是四个流派并列，是同一条压缩链上的四道工序：

| 来源 | 工序 | 给什么 |
|---|---|---|
| 经典骨架（《子平真诠》系） | ②方向 + ⑤边界 | 定轴与法度 |
| 巾箱秘术 | ①条件 | 圈域（锁死在日柱×月令） |
| 道秀说易 | ④机制 | 做功路径与时间窗 |
| 案例库 | ③**强度** | 唯一能算频率、算超额、算样本量的东西 |

四源**共用同一事实层，不是互相验证**。

---

## 三道闸（防自欺）

跑几千条案例做筛选，最大的敌人不是数据不够，是**多重比较 + 选择偏差 + 悄悄丢**。三道闸对治：

1. **归组** —— 条目归到「方向轴」（十神×事类、格局×事类……十来根）。校正单元是**轴的数**，不是条目的数。实测：48 条 → 11 轴，判据线从 3.42 压回 **2.84**。
2. **两段式** —— 库切两半：一半「发现」（宽进），一半「确认」（严出）。**只在没看过的那半复现的，才准进「敢说清单」。**
3. **未蒸清单** —— 蒸馏必然有落不下的（纯形容词、无条件的格言）。**登记在册写明为什么没蒸，不许偷偷丢。**

## 首批结果（48 条 / 11 轴）

判据线**先写死再跑**（11 轴 ⇒ 2.84，双侧 0.05）。两段分半 + 两源交叉。

**A 档（唯一全过关）**：`偏财（全字口径：干支 8 字 ＋地支藏干）≥1 → 财`。
「两个测法 × 两份记录 × 两半数据」八个格子方向全一致；阴性对照「正财」全平 —— 不是"有财星就好"，是**偏财这个字本身有效**。
第四轮加「出口健康度」闸后复检仍成立：它落在**健康出口**（财域等级 4~5 档、凶率 40~46%）上，不是靠稀疏事件撑出来的。

**切细**：给偏财叠宫位后发现，**落在日时（主位）管用，落在年月（祖上宫）基本不管用**；透干无根反而好过藏在年月 —— **位置比根气更管事**。（探索性，须前瞻坐实）

**B 档（一致但强度不足）**：8 条待观察。

> **显式撤回**：早前列为 B 档首位的「伤官见官（坤造）→ 婚姻差」**已作废**。它当时跑在**病列** `gender` 上
> ——该列把每批第一例的性别盖给全批（含 ≥2 例的批次里 0 个混合）。性别修复后，该条目在干净池上**全平**。
> 详见 [`results/verification-3.md`](results/verification-3.md)。

**D 档（测不动）**：9 条因靶域**没有出口**（刑灾官非 54 例全是凶、零吉向）而测不出 —— 由此得到一条新纪律：**出口先于条目**。
第四轮给这个域**造了出口**（域内严重度：口舌 < 官司 < 牢狱 < 刑伤，94 例 / 3 档 / H=0.59）后复测，
9 条**全部仍然平**。正确说法从「测不动」变成「**测了，没有**」——两者必须分开报。

详见 [`results/verification-1.md`](results/verification-1.md)、[`results/verification-3.md`](results/verification-3.md)、[`results/entry-list.md`](results/entry-list.md)。

**第三轮（变量修复）**：发现分组变量 `gender` 是病列 → 用「四柱锚点 + 案例切块」重建（覆盖 65.2%，两把互不
相看的读数 98.9% 一致）→ **女命轴五条在干净池上全平**，旧榜首 +2.12 系脏池造的假信号。**教训：一个变量脏，
整条轴作废；「资料不足」与「无信号」必须分开报。**

**第四轮（拓出口 + 底账）**：给结果出口加了「健康度」闸 —— 二值出口基线率必须在 5%~95% 内，序数出口必须
≥3 档且分布不塌。一闸下去，原来 13 条「两半一致」里 **4 条坐在退化出口（功名凶率只 4%）上、3 条坐在代理出口上**，
真正落在健康靶域出口的只剩 5 条。同轮把条目册的状态栏**改为由打分器机器写入**：一写就暴露 **15 条「手写说
有结果」的条目，换口径后全平**。**教训：清单一旦与实测脱钩，「敢说的有几条」就不可信。**

详见 [`docs/outlet-inventory.md`](docs/outlet-inventory.md)、[`docs/entry-battery-run4.md`](docs/entry-battery-run4.md)、[`results/verification-4-score.txt`](results/verification-4-score.txt)。

**第五轮（修根：比肩）**：`build_ruler8.py` 第 79 行把**日干自己**也拿去数十神，而
`ss(日干, 日干)` 恒等于比肩 ⇒ 全库每例比肩 ≥1，「比肩=0 / 比劫=0」**永不成立**，
整条比劫轴白跑且**毫无报错**。修根（`fix_shishen_root.py`，`ruler_ver=2`，日主排除，
旧值留档 `bijian_v1`）后比肩 0 组 **0 → 587（25.3%）**，落进其余九神的正常区间；
不变式核对「新 = 旧 − 1」差异 **0 例**，另抽一造**手算逐格相符**。
连带揪出三处：**下游兜底没撤导致的「双重扣减」**、女命脚本含日主（全库 2322 例身强指标恒高 0.5）、
断命脚本**按字面**排日干（10.2% 的造少算一格）。
**教训：修根后必须回收全部兜底补丁；兜底要写成条件式，别写成常数——常数会在修根那天变成新 bug。**

详见 [`docs/bijian-root-fix.md`](docs/bijian-root-fix.md)。

**第七轮（条目册自动化：消掉两份真相）**：自审查出真伤「条目条件 ≠ 实测判据」——
同一个条件存了两份：打分器里的**判定函数**（真值）和条目册里**手写的 cond 文字**（复制品）。
手写「偏财≥1」，打分器却按**原始计数梯度**测。修法是消掉一份：条件写成一个 **DSL 规格**（`pipeline/entries_spec.py`），
`build()` 出判定、`render()` 出中文 ⇒ **文字与判定同源，物理上不可能不一致**；`status/res/grade` 由打分器机器写入，
手写降级为冻结备注（漂移表留作体检）。纪律落成**可复跑三闸** `pipeline/verify_entries.py`：
判定等价（全库 **97524 个判定值 0 不一致**）、条件同源（0 不符）、无手写残留。
**闸门当场抓出真 bug**（`carr` 原子把列表参数当变参传，2322 例全错）——没这道闸，它会静默进产线。

详见 [`docs/entry-registry.md`](docs/entry-registry.md)、[`docs/entry-list.md`](docs/entry-list.md)。

## 数据与伦理声明

- **本仓库不含案例库原始数据。** 案例库是真人案例，涉及隐私，且体例源自出版物，不公开、不传播。
- 仓库内的脚本**读取你自己构建的案例库**（SQLite）；公开部分只包含**方法与流程**，以及**不含可识别个人的聚合结论**。
- 所有结论均**绑定口径声明**。换口径翻盘必须显式撤回。
- 命理是**路况图，不是判决书**。本仓库不提供对任何具体个人的断语服务。

## 复现

流水线假设案例库为 SQLite，且含以下结构（自建）：

- `cases` —— 四柱、十神（干支 8 字 **＋地支藏干**）、通根、合冲会刑、宫位、大运

> ⚠️ **十神口径（2026-10-07 修根）**：日主是参照点，**不该给自己安十神**。
> 早先版本把日干算成比肩（比肩组 0 → 587），已修为 `ruler_ver=2`：
> 正确读列是 `shishen_quan` / `shishen_tiangan`；旧列 `shishen_config` 只作历史留档，**禁用于新分析**。
- `case_outcomes` —— 分域结局（域 × 吉凶 × 等级）

```bash
python3 pipeline/build_entry_list.py    # 四源 → 条目清单（entry-list.md + entries.json）
python3 pipeline/score_entries.py       # 上机打分（按轴归组 + 分半 + 预注册线）
python3 pipeline/refine_piancai.py      # 对幸存条目做切细实验
python3 pipeline/verify_entries.py      # 条目册三道闸：判定等价 / 条件同源 / 无手写残留

# 自审装置（方法的一部分，同样公开）
python3 pipeline/pred_power.py table                    # 预测力功效表：猜对几条才算本事
python3 pipeline/pred_power.py check --n 2 --k 2 --p0 0.5
python3 pipeline/self_audit.py --ledger list            # 前瞻账本（账目文件是当事人私事，不入库）
python3 pipeline/ledger_due_nag.py                      # 到期催账：没事静默，到期才出声
```

> 📌 **预测力课题（新增）**：解释力已在库内封顶 🥈B「库内最强（未经盲测）」；
> 想进 🏅A「敢说」只有一条路——**前瞻盲测命中 ≥2 次**。详见
> [`docs/prediction-power.md`](docs/prediction-power.md)。
> 一句要紧的实话：**命中 ≥2 只是入场券**（2/2 全中、基线 50% ⇒ p = 0.25），不是「已证明」。

输出默认落在脚本同级目录，请按自己的库路径调整连接串。

## 边界

这套东西解决的是**解释力**（一条断语站不站得住），**不是预测力**。
预测力要靠**先断后对**的闭卷验证（封存结局、只给八字、先断再揭晓），以及长期前瞻账本 —— 那是下一个课题。
