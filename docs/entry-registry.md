# 条目册「禁手写」装置（消掉两份真相）

> 2026-10-07 ／ 任务11 ／ 出处：自审 `audit-self-2026-10-07.md` 真伤 ⑤「条目条件 ≠ 实测判据」

## 1 病是什么

同一个「条目条件」曾**存在两份**：

| 份 | 在哪 | 性质 |
|---|---|---|
| 判定函数 | `distill/score_entries.py` 的 `P` 表（lambda） | **机器真值**（真正在跑的判据） |
| 条件文字 `cond` | `distill/entries.json`（人写的） | 会漂移的副本 |

实测偏差：偏财条目手写「**偏财≥1**」，而打分器实际按**原始计数 0/1/2/3 的梯度**测（z=+3.30 是首末档对比，不是二分对比）。
——**读条目册的人拿到的判据，不是打分器用的判据。**这不是笔误，是结构病：**同一事实存两处，必漂移**。

同一结构病还有两处变体：
- `name`（条目名）里重述条件（「偏财≥1 → 财等级↑」）⇒ 同样会漂移；
- `status` / `res`（结果）手写 ⇒ 跑了新测量不回写，20 条僵在「待测」，首次机器回写即暴露 **15 条「手写说有结果」而换口径后全平**。

## 2 修法：条件只写一次，文字与判定同源

新增 `distill/entries_spec.py` ＝**条目条件的唯一定义处**。一条条件写成一个 **DSL 规格**，它同时生成两样东西：

```
spec（DSL 一行）
 ├─ build(spec)  → 判定函数（打分器唯一使用的判据）
 └─ render(spec) → 中文条件文字（条目册唯一使用的 cond）
```

⇒ 文字与判定**物理上不可能不一致**：改规格，两边同时改；不改规格，两边都动不了。

```python
("AX01-01", "财", +1, None, {"k": "ss", "n": ["偏财"], "mode": "count"}),
#                                 └ 判定=原始计数      └ 渲染=「偏财计数（原始计数 0/1/2/3，未二值化）」
```

### DSL 原子（够用即止）

| `k` | 含义 | 关键参数 |
|---|---|---|
| `ss` | 十神个数（**全字口径·含藏干**，日主不计，`ruler_ver=2`） | `n`=名字表，`mode`=`count`(原始计数)／`gt0`／`eq0`／`ge`+`k`／`ord_gt0`（>0 才计入的计数）／`ord_range`+`lo,hi` |
| `ssc` | 十神个数（**天干口径**，旧尺） | `n` |
| `tg` | 某十神在指定柱的天干上 | `n`,`pos`(年/月/日/时),`want`=False 表示"不透于" |
| `zhi` | 日支被冲/合/刑 | `lst`=`ch`／`he`／`xing` |
| `wx` | 五行缺一 / 任一≥K | `mode`=`missing`／`ge` |
| `pillar_set` | 任一柱地支落在某集合 | `set` |
| `yl_day` | 月令∈A ∧ 日干∈B ∧ 五行C=0（调候） | `yl`,`day`,`wx` |
| `all` | 合取（成员一律二值原子） | `x`=[...] |
| `carr` | 财富载体序数（财0<食伤1<官杀2） | — |

另有两条**声明但未建**的类别（不许默默省略，见「闸三」）：
- `kind="declared"`：已声明、判定函数未建（库缺字段／算法／结局域）—— cond 是声明文字，**明标〔未蒸〕**，不进统计层；
- `kind="method"`：口径效应（尺子）——不是理论条目。

## 3 三道闸（纪律写成可复跑的检查）

`distill/verify_entries.py`，任一不过即非零退出：

| 闸 | 查什么 | 判据 |
|---|---|---|
| 闸1 **判定等价** | 新规格表 vs 老打分器（`score_entries_legacy.py` 留作回归基准） | 全库逐例逐条比对，不一致数必须 **0** |
| 闸2 **条件同源** | 册子里每条 `cond` 是否等于 `entries_spec` 现场渲染 | 差一个字符即失败 |
| 闸3 **无手写残留** | 册子里有没有冻结的手写 cond 原文／手写 status 字段 | 出现即失败 |

### 实测结果（2026-10-07）

```
闸1 判定等价：97524 个判定值，不一致 0 个 ✅
闸2 条件同源：机器判定 42 条 ｜ 不符 0 ✅
闸3 无手写残留：手写 cond 原文出现 0 处 ｜ 手写 status 字段 0 处 ✅
```

对照：`score-splithalf.txt` 与重构前**逐行零差异**（仅 AX09-05/04 两行按编号规整了位置），连跑两次输出一致。

**闸1 抓到的真 bug**（说明这闸不是仪式）：`carr` 原子的新实现在把 `ss_sum(f,"正官","七杀")` 当变参传，而函数签名是列表 —— 42 条里 41 条逐例一致，唯独 AX11-01 起 2322 例全错。**没有闸1，这个错会静默进产线。**

## 4 条目册字段：谁写谁不许写

| 字段 | 谁写 | 说明 |
|---|---|---|
| `cond` `cal` `dir` `name` | **脚本渲染**（`entries_spec`） | 禁手写。`name` = `cond → dir`，不再手抄条件 |
| `status` `res` | **打分器机器写入**（`score-splithalf.txt`） | ❌ 手写 |
| `grade` | **机器写入**：前瞻账本命中 ≥2 ⇒ A；库内跨源×跨半一致 ⇒ B；单源/单半 ⇒ C；已测全平 ⇒ ✗；测不动/未跑 ⇒ — | A 只能由前瞻进货，**库内封顶 B** |
| `variants` `variant_of` `alias_of` | **脚本生成**（家族表 + 自动补登） | 变体/本体关系显式声明，不再靠编号猜 |
| `mech` `bnd` `src` | 人写（散文） | 只剩这三样；**冻结于 `entry-prose.json`** |
| `stamp` | 脚本 | `score-splithalf.txt` 的 md5 + `K_TESTS` + `ZC` + `ruler_ver` + 十神列名 + 口径 —— **口径绑声明**：数字离开这枚戳就不算数 |

**漂移本身留作体检结果**：`entry-prose.json` 冻结了改造前的手写状态，生成器每次打印「手写 vs 机器」漂移表（A 类＝手写有结果而现行口径全平，14 条；B 类＝手写滞后，21 条）。手写降级为**备注**，不再是状态。

## 5 加新条目怎么走

1. 在 `entries_spec.py` 的 `SPEC` 里加一行 `(编号, 域, 符号, 门控, DSL)`；没判据的先加进 `EXTRA` 标 `declared`；
2. 若该形需要新原子：先想清楚**判定与渲染是否都能从同一个 spec 推出**——推不出就说明这个条件还没想清楚；
3. 跑 `python3 distill/score_entries.py`（出新测量）→ 跑 `python3 distill/build_entry_list.py`（回写 status/grade）；
4. 跑 `python3 distill/verify_entries.py`，三道闸全过才算落地；
5. 记 `stamp`：**数字 + 版本 + 尺 + 时点** 一起说。

## 6 纪律

- **一条条件只许写一处**：写两处就是埋一颗定时炸弹，早晚炸在「读册子的人以为的判据 ≠ 打分器用的判据」上。
- **纪律要写成可复跑的闸门**，否则它只在你记得的时候存在。
- **手写降级不等于删除**：冻结留档，让「漂移」本身变成体检证据。
- **改了上游（规格表）必须重跑闸1**：等价性是「重构没改行为」的唯一证明。
