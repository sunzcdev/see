# 出口换源：从「我的批注」到「原作者原文」

> 触发问题（用户 2026-10-07）：「**你现在是在拿库里的案例验证自己的skill吗？**」
> 这一问问出了库里最贵的一个结构错误。全文是实录，方法已提炼回 SKILL.md 第 8 节。

## ⚠️ 更正（2026-10-07 晚，用户指正后复核）

**本文原先把病因报成「数据源脏 / 循环论证」，这个定性错了。** 用户指正：语料从采集、过滤到验证是一环环清洗过的；其中附带的结论也是**从原文得到的**（原命理记「此人离婚」，八字交叉验证也是「离婚」，故记为离婚）——**不是我的臆想。两套理论指向同一结果叫「殊途同归」，殊途同归恰恰证明两法都有效，不是自己验证自己。**

复核成立。逐条更正：

| 原判 | 更正 |
|---|---|
| 「63% 结局取自我们自己的批注 ⇒ 循环」 | 结局句里**事实与解释并存**是正常写法。「含命理术语 93%」测的是**句式**，不是**出处**。事实是谁先记录的？——**巾箱原作者**，我们只是复述 + 复核 |
| 「所以要清洗数据源」 | 病灶不在语料，在**我的第一版抽取器**：它按段落优先级取「结局」，取到【方法论】（我的归纳）而非【断语回溯】/【排盘核验】（原文事实 + 复算）⇒ **造出一个带归纳色彩的变量**。改工具即可，不需要洗数据 |
| 「换独立源头后 8 条只剩 1 条 ⇒ 原来大半是假的」 | 两组变量的**测量程序不同** ⇒ 7 条死掉的含义是「**换测量后不复现**」，**不等于「原来是假的」** |
| 「独立 = 换作者」 | 更正为：**独立 = 盲（做这次判断时知不知道答案）**。读过答案的第二作者不独立；同一作者的前瞻盲测独立 |

**复核证据**：我方核验本来就**敢跟原文顶**——第 225 批抓出「1964 年丙戌月内无丙辰日」判为转录错、正确年份 1965，并标「戊申 = 命主 3 岁未起运，断语归属存疑」。**照抄抄不出这种顶牛。** 这一条本身就是「复核层独立于原文」的实证。

**仍然成立的两点（与真伪无关，是限制）**：
1. **采样天花板**：案例是巾箱按自家口诀挑的 ⇒ 高命中率只能读作「在自身样本内解释得住」，**不可外推成理论准确率**。清洗解决不了，只能靠前瞻盲测对冲。
2. **「另一套理论解释同一批事实」这一层还不构成殊途同归**——因为解释是在读到原文结论之后做的，**没盲**。要让殊途同归算数，必须补盲测（前瞻账本即此装置）。


## 一、结论先行

**不是在验证 skill（skill 是流程，只能被用、不能被验证），但也比"在验证命理"更糟：**
**我原来是在自己的批注上给自己打分。**

| | 源A 回复层（旧） | 源B 素材层（新） |
|---|---|---|
| 文本出处 | `batches.reply` —— **我们自己写的核验回复** | `batches.content` —— **巾箱源作者写的原文** |
| 结局段落 | 63% 取自【方法论·铁律归属】＝**我的命理批注** | `[原文首段]` 里的真实人生事实 |
| 可分类 | 879 例 | **1576 例** |
| 有等级 | 499 例 | **1009 例** |
| 性质 | **循环源**（拿命理结论检验命理结论） | **独立源** |

## 二、怎么发现的（诊断顺序，可复用）

1. **数段落名**：`select reply` → 正则抓 `【…】`。815 批实测：
   【资产】524、【排盘核验】520、【**方法论·铁律归属**】429、【断语回溯】**仅 16**。
   → **标准版式是「排盘核验 → 方法论·铁律归属 → 资产」，里面根本没有"结局"段。**
2. **改段落优先级**（把客观段排在批注段前），结果**可分类量反而从 883 掉到 245** —— 因为 1506 例落到了【排盘核验】（纯粹的四柱/日历）。
3. **回头问一句**：那"结局"到底存在哪？→ 查 `batches` 表结构，发现 **`content` 字段（原始素材）一直躺在库里**。
4. 抽 `content` 一看：**`[原文首段]` 里全是源作者写的客观事实** ——
   「流年庚申，父亲因肺病住院」「流年癸亥，患眼病致使左眼失明」「大运庚戌，流年戊寅结婚」。
5. 再查，发现**同一套口径坤造 102 例早就做过**（见 `kunzao-extraction-audit.md`：「不是缺数据，是缺提取」）。
   → **我在全库这一遍偷懒了：坤造照原文抽，全库却从自己的回复里抽。**

## 四、方法论回报（比数据回报值钱）

### 1. 「两把秤读数一致」是假独立
上一轮我说：「偏财在吉凶秤 + 等级秤上都同向 ⇒ 两种仪器读数一致，比单秤重复值钱」。
**错。两把秤读的是同一批数据（都是我的批注），换口径不等于换源头。**
真独立只有一条判据：**换作者** —— 换一个不是由被测方法生产出来的文本源。

呼应 `mingli-self-audit` 的四层独立度：源A 属 **L1（自述）**，源B 才够 **L4（现实回报）**。

### 2. 出口的独立性比出口的分辨率更优先
前一轮我修了出口的**粒度**（吉/凶 → 等级），以为够用了。
真相：**粒度再好，源是自己写的批注，测出来的仍是自己的影子。**
⇒ 修出口的顺序应是：**先问"这句话谁写的"（独立性），再调"记成几档"（分辨率）。**

### 3. 忠诚于格式会掩盖源头错误
我的抽取出句器**老老实实按段落优先级取**，取出来的正是【方法论】——它工作得很好，只是**取错了地方**。
⇒ **调试抽取器之前，先确认被抽取的文本本身配不配当证据。**

## 六、踩过的坑（脚本层）

| 坑 | 症状 | 修法 |
|---|---|---|
| **cursor 复用** | 内层 `cur.execute` 打断外层迭代 → 815 批只处理了 13 块 | 先 `fetchall()` 物化外层，或另开 cursor |
| **`create table if not exists`** | 旧表结构残留 → 「9 columns but 10 values」 | 改表结构时用 `drop table if exists` 先删 |
| **case_no 跨批复用** | 用它配 case_id 会张冠李戴 | **批内块序 + 四柱校验**配对（本脚本 pil_ok 字段记录校验结果） |
| **诀言诗句** | 「亥子多见防目凶」被当成结局断语 | 引号内诗句先挖成占位符再分类 |
